# Pi configuration

Seed's backend launches middleman, worker, and a lazy control Pi process using the shared directory selected by `PI_CODING_AGENT_DIR` (or the Seed runtime directory). On Android, `/home/seed/.pi/agent` is a PRoot bind mount of the app-private `filesDir/linux/pi-agent` directory, outside the replaceable rootfs. The terminal uses the same mount. The directory contains native Pi `settings.json` and `auth.json`. Pi reads settings defaults when the backend starts an agent without an explicit selection; the backend does not inject default provider, model, or thinking flags or use `SEED_PI_*` as a fallback. An explicit Settings apply passes the selected provider, model, and thinking level to the chat agents and writes the native settings file.

The control process uses no tools, extensions, skills, or project context. An explicitly scoped provider can use `--models provider/*` for catalog discovery without choosing a hardcoded model. Before a model is selected, startup failures of chat agents do not prevent the control endpoints from being used. To reload a catalog after changing Pi configuration from a shell, request `GET /control/v1/models?refresh=true`; this restarts the lazy control process so it rereads Pi files. `GET /control/v1/config` reads the native files on each request.

Provider login is saved in `auth.json`, not in Android's encrypted preferences. The backend avoids returning key material from its configuration and model endpoints and strips curated credential environment variables and its runtime capability token from Pi children. This is **not** a guarantee of secret isolation from shell access or other processes running with the same guest user: filesystem permissions and the guest runtime determine who can read Pi's auth file. Protect the guest filesystem and backups accordingly. Save login confirms local persistence, not remote provider authentication.

For local development, configure Pi's native files in the selected agent directory and start `./backend/scripts/dev.sh`. Do not commit `auth.json` or keys. The middleman is restricted to read-only tools (`read,grep,find,ls`); the worker has editing tools. Both receive their role prompts and the generated app URL. The generated Flask app runs separately on port 7778 from FastAPI on port 7777.

Run backend tests with `cd backend && .venv/bin/python -m pytest tests`.
